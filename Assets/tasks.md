# Проблема с imm6 и как её решают настоящие 8-битные CPU

Если регистр 6-битный (0–63), то у команды `ADDI/ANDI/ORI/XORI/CMPI Rd, #imm` действительно логично требовать полный 6-битный immediate, а не урезанный imm3 — иначе такими командами нельзя работать со старшими битами вообще.

Но арифметика бит здесь простая и неумолимая: слово = 12 бит, регистр-приёмник (из 8 шт.) = 3 бита, immediate = 6 бит → **на код операции остаётся ровно 3 бита**, если мы хотим и LDI, и ADDI, и SUBI, и CMPI, и ANDI, и ORI, и XORI одновременно — итого 7 разных команд, которым нужно где-то взять код операции, а бюджет для этого — либо 3 бита (8 вариантов, впритык хватает), либо надо чем-то жертвовать.

Именно эту задачу вы уже интуитивно нащупали, когда просили косвенную адресацию "как в ATmega" — и у AVR есть готовое решение **ровно этой же проблемы**: команды с immediate (`ANDI`, `ORI`, `SUBI`, `CPI`, `LDI`) в AVR умеют адресовать не все 32 регистра, а только верхние 16 (`r16–r31`) — именно чтобы освободить бит под полноценный 8-битный immediate. Я предлагаю сделать то же самое: **immediate-команды работают только с R4–R7** (2 бита на регистр вместо 3), а обычные регистро-регистровые операции по-прежнему видят все 8 регистров.

Важно: **Z = R7 попадает в этот диапазон**, так что `LDI Z, #addr` с полным 6-битным адресом остаётся доступен без проблем — вы не теряете самую важную операцию (установку указателя).

# Итоговая раскладка 12 бит

## Класс A — immediate-операции (бит 11 = 1)

`1 ooo rr iiiiii` → op(3) + reg(2, только R4–R7) + imm(6)

| ooo | Мнемоника | Действие | Флаги |
|---|---|---|---|
| 000 | `LDI Rd,#i` (Rd∈R4–R7) | Rd = i | — |
| 001 | `ADDI Rd,#i` | Rd += i (mod 64) | Z,C,N |
| 010 | `SUBI Rd,#i` | Rd -= i (mod 64) | Z,C,N |
| 011 | `CMPI Rd,#i` | Rd - i, без сохранения | Z,C,N |
| 100 | `ANDI Rd,#i` | Rd &= i | Z,N |
| 101 | `ORI Rd,#i` | Rd \|= i | Z,N |
| 110 | `XORI Rd,#i` | Rd ^= i | Z,N |
| 111 | *резерв* | | |

Полный 6-битный immediate есть **у всех семи** команд этого класса — вот ради чего пожертвовали доступом к R0–R3 именно здесь. Кстати, `SUBI` формально избыточна (`SUBI Rd,#i` ≡ `ADDI Rd,#(64-i) mod 64`, поскольку арифметика и так mod 64), но я оставил её отдельной командой ради удобства человека, который пишет программу руками — слот всё равно был свободен.

## Класс B — регистр-регистр АЛУ (000, все 8 регистров)

`000 ooo ddd sss`

| ooo | Мнемоника | Действие | Флаги |
|---|---|---|---|
| 000 | `MOV Rd,Rs` | Rd = Rs | — |
| 001 | `ADD Rd,Rs` | Rd += Rs | Z,C,N |
| 010 | `SUB Rd,Rs` | Rd -= Rs | Z,C,N |
| 011 | `CMP Rd,Rs` | Rd - Rs, без сохранения | Z,C,N |
| 100 | `AND Rd,Rs` | Rd &= Rs | Z,N |
| 101 | `OR Rd,Rs` | Rd \|= Rs | Z,N |
| 110 | `XOR Rd,Rs` | Rd ^= Rs | Z,N |
| 111 | **EXT** — `sss` становится под-опкодом (см. ниже) | | |

При `ooo=111` поле `sss` — унарная операция над `Rd` (регистр из полных 8, включая R0–R3 — здесь как раз компенсируется ограничение класса A):

| sss | Мнемоника | Действие | Флаги |
|---|---|---|---|
| 000 | `NOT Rd` | Rd = 63 - Rd | Z,N |
| 001 | `LD Rd,(Z)` | Rd = Data[Z mod 36] | — |
| 010 | `ST (Z),Rd` | Data[Z mod 36] = Rd | — |
| 011 | `LSL Rd` | Rd <<= 1 (mod 64), C = выпавший бит | Z,C |
| 100 | `LSR Rd` | Rd >>= 1, C = выпавший бит | Z,C |
| 101 | `ROL Rd` | циклический сдвиг влево через C | Z,C |
| 110 | `ROR Rd` | циклический сдвиг вправо через C | Z,C |
| 111 | *резерв* | | |

`001 ooo aaaaaa`, адрес 6 бит (0–35 используются из 64 возможных)

| ooo | Мнемоника | Условие |
|---|---|---|
| 000 | `JMP addr` | безусловно |

| 010 | `BRNE addr` | Z=0 |

| 100 | `BRCC addr` | C=0 |

| 110 | `BRPL addr` | N=0 |
| 111 | *резерв* |

| `DJZ Rd,addr` | Rd -= 1; если Rd=0 → JMP addr |

## Класс E — резерв (011)

9 бит полностью свободны — под будущее (например, `CALL/RET` для подпрограмм или прямая абсолютная адресация Data без Z, если позже понадобится).

# Проверка покрытия

- Всего пространство 4096 кодов, коллизий нет: биты 11 / 11-9 однозначно разводят классы A/B/C/D/E, дальше внутри каждого класса под-опкоды не пересекаются.
- Все ранее "бесполезные" imm3-команды (ADDI/SUBI/ANDI/ORI/XORI/CMPI) теперь имеют полный imm6 — единственная цена: они видят только R4–R7 вместо R0–R7.
- Явно зарезервировано: 1 код в классе A, 1 в классе B (unary), 1 в классе C, весь класс E (011) — есть куда расти, если по ходу тестирования модуля выяснится нехватка.

Если хотите, могу пересчитать набор задач из первого сообщения под это ограничение "immediate только для R4–R7" — там, где значение сначала вычисляется в R0–R3 (например, результат `ADD`/`AND` с данными из памяти), придётся добавлять явный `MOV` в R4–R7 перед тем, как использовать `CMPI`/`ANDI` и т.п., и это стоит учитывать в оценке "уместится ли в 36 слов".



# Что меняю

1. Убираю ограничение «без буферного регистра» в задаче про обмен (и подобные implementation-ограничения в других задачах) — раз проверяется только финальное состояние, такое условие всё равно невозможно проверить, а значит оно бессмысленно.
2. Слишком короткие задачи (проверка чётности, единичный доступ к Data, разница двух чисел и т.п.) — либо объединяю по несколько в одну составную задачу, либо заменяю на более содержательные (Коллатц-подобный процесс, медиана трёх чисел, popcount и т.д.), либо ввожу цикл там, где раньше было прямое вычисление.
3. Раздел с JOP полностью переосмыслен: раз `JOP` — это переход по **константному** адресу (не по значению регистра), а обычная последовательная лента исполнения и так спокойно "перетекает" со страницы 0 на страницу 1 без всяких скачков, то настоящая необходимость в `JOP` возникает только в двух случаях — (а) нужно попасть в **конкретную ненулевую точку** другой страницы (простое перетекание приведёт в её самое начало, а не туда, куда нужно), и (б) нужно **вернуться назад** на более раннюю страницу. Все задачи раздела E построены именно на этом принципе, а не на искусственном «часть кода тут, часть там».

## A. Регистровая арифметика и логика (без Data)

1. Даны три регистра — расположить их значения по возрастанию (отсортировать на месте).
2. Даны три регистра и регистр-результат — записать в результат медиану (по значению, не по позиции) этих трёх чисел.
3. Дан регистр R (1–63) — вычислить, за сколько шагов процесс «если чётно — делить пополам, если нечётно — утроить и прибавить 1 (по модулю 64)» приведёт R к значению 1; число шагов — в регистр-результат. Гарантируется, что процесс завершится не более чем за 30 шагов.
4. Даны Ra, Rb — вычислить одновременно: |Ra−Rb| в Rc, (Ra+Rb) mod 64 в Rd, и признак чётности этой суммы (0/1) в Re.
5. Дан регистр R, число сдвигов N и направление D (0 — влево, 1 — вправо) — выполнить циклический сдвиг R на N позиций в указанном направлении.
6. Дан регистр R и регистр-результат Rc — посчитать количество единичных битов в R (0–6).
7. Дан регистр R и регистр-результат Rc — определить, является ли значение R степенью двойки (1, 2, 4, 8, 16, 32), с учётом того, что 0 степенью двойки не считается.

## B. Составной доступ к Data (пара ячеек)

8. Даны адреса A, B, C и регистр-результат R — записать в Data[C] сумму Data[A] и Data[B] по модулю 64; если при сложении произошёл перенос (сумма без учёта модуля превысила 63) — дополнительно записать 1 в R, иначе 0.
9. Даны адреса A и B — если значение по адресу A больше значения по адресу B, поменять их местами, иначе оставить без изменений.
10. Даны адрес A, значение V и регистр-результат R — если Data[A] больше V, увеличить Data[A] на 1, иначе уменьшить на 1 (по модулю 64); в R записать 1, если значение увеличилось, иначе 0.

## C. Циклы по диапазону Data

11. Даны адрес A, длина N и регистр-результат R — просуммировать N подряд идущих байт начиная с A (по модулю 64).
12. Даны адрес A, длина N и регистр-результат R — найти максимальное значение среди N байт начиная с A.
13. Даны адрес A, длина N, искомое значение V и регистр-результат R — найти адрес первого вхождения V среди N байт начиная с A; если не найдено — записать 63.
14. Даны адрес A, длина N и два значения V1, V2 — заполнить чётные по счёту позиции диапазона значением V1, а нечётные — значением V2.
15. Даны адрес A и длина N — развернуть N подряд идущих байт начиная с A в обратном порядке, на месте.
16. Даны адрес A, длина N и регистр-результат R — посчитать сумму абсолютных разностей между каждой парой соседних элементов диапазона.
17. Даны адрес A, длина N и адрес B (диапазоны не пересекаются) — скопировать диапазон Data[A..A+N) в Data[B..B+N) в обратном порядке (последний элемент источника становится первым элементом приёмника).
18. Даны адрес A, длина N и регистр-результат R — определить, отсортирован ли диапазон по неубыванию (0/1).

## D. Ветвления и классификация

19. Даны регистр R, границы LOW и HIGH (LOW ≤ HIGH) и регистр-результат Rc — записать в Rc: 0 если R < LOW, 1 если LOW ≤ R ≤ HIGH, 2 если R > HIGH.
20. Дан регистр R, делитель K (K≠0) и регистр-результат Rc — если R делится на K нацело, записать 1, иначе — остаток от деления.
21. Даны адреса A, B и C — сравнить Data[A] и Data[B], записать по адресу C: 0 если равны, 1 если Data[A] больше, 2 если меньше.
22. Дан регистр-счётчик R, предел LIMIT (>R) и регистр-флаг Rf — увеличивать R на 1 в цикле, пока не достигнет LIMIT, после чего установить Rf = 1.
23. Даны адрес A, длина N, искомое значение V и регистр-результат R — определить, встречается ли V хотя бы раз среди N байт начиная с A (0/1).
24. Даны адрес A, длина N и регистр-результат R — посчитать количество «локальных максимумов» в диапазоне (элемент строго больше обоих соседей; крайние элементы не учитываются).

## E. Работа со страницами (JOP)

25. Дан флаг Rf (0/1), адрес A, константа K и два адреса P0, P1 на второй странице программы — на этих адресах должны быть расположены два готовых обработчика (P0: увеличить Data[A] на K; P1: уменьшить Data[A] на K); в зависимости от Rf с первой страницы передать управление нужному из них через `JOP`.
26. Дан регистр-селектор R (0–3), адрес A, константы K0..K3 и адреса P1, P2, P3 на второй странице — если R=0, прибавить K0 к Data[A] прямо на первой странице; если R=1/2/3 — перейти по соответствующему адресу P1/P2/P3 на второй странице и прибавить там K1/K2/K3.
27. Дан флаг Rf, два набора параметров (адрес A1/длина N1 для одной операции и адрес A2/длина N2 для другой) и адрес P на второй странице — если Rf=0, просуммировать диапазон (A1,N1) на первой странице; если Rf=1 — перейти по P на второй странице и найти там максимум диапазона (A2,N2); в обоих случаях результат — в регистр-результат R.
28. Дан адрес A, число раундов N и адрес P на второй странице — организовать цикл из N раундов, где на чётных по счёту раундах над Data[A] выполняется одно действие (например, увеличение на 1) на первой странице, а на нечётных — другое действие (например, уменьшение на 1) через переход по P на второй странице; после каждого раунда на любой странице управление должно возвращаться к счётчику раундов, расположенному на первой странице.
29. Даны флаг Rf, значения V0 и V1, регистр-результат R и адрес P на второй странице — если Rf=0, записать V0 в R кодом на первой странице; если Rf=1 — перейти по P на вторую страницу и записать там V1 в R.
30. Даны адрес A, длина N, порог T и два адреса P_low, P_high на второй странице — найти минимум диапазона Data[A..A+N); если он меньше T — перейти по P_low и записать в регистр-результат 1, иначе перейти по P_high и записать 0.

## F. Продвинутые задачи над диапазонами

31. Даны адрес A, длина N и делитель K (K≠0) — заменить каждый байт диапазона на остаток от деления этого байта на K.
32. Даны адрес A и длина N — вычислить целочисленное среднее значений диапазона (округление вниз), результат — в регистр-результат.
33. Даны адреса A, B и длина N (диапазоны одинаковой длины, не пересекаются) — поэлементно сложить Data[A..A+N) и Data[B..B+N) по модулю 64, результат записать поверх диапазона A.
34. Даны адрес A, длина N и регистр-результат R — посчитать, сколько элементов диапазона больше среднего значения этого же диапазона (среднее вычислить как часть решения, округление вниз).
35. Даны адрес A и длина N — отсортировать диапазон Data по возрастанию, на месте.
36. Даны адрес A, длина N, значение V и регистр-результат R — сдвинуть весь диапазон на одну позицию вправо (по адресу A записать V), а значение, выпавшее за пределы диапазона, сохранить в R.
